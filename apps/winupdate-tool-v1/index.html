Why I built it

This one started on my own PC. Something broke, and I had neither the time nor the patience to reformat. Windows Update kept recommending a “reinstall” of Windows, and every attempt failed.

Maybe, then as now, Microsoft holds back upgrades on PCs older than 8th-generation Intel on purpose. I understand why: newer hardware has security features built in. But for people who just want their PC to work, it makes no sense, because those PCs work very well regardless.

So I set out to build a tool that behaves like a system I’ve managed for a long time at several workplaces: BigFix, where a managed agent does the work in large organizations. I wanted something like it for the personal world, the free world, as I like to call it. After all, that’s the world I grew up in and came up from.

And that’s what happened: I built a tool that worked around my problem.

How it grew

  • May 2025First build: one small EXE
  • Jun 20261.1.2: MSI, portable EXE and command line
  • Jul 2026Published on GitHub; V2 takes over

What it does

  • A window to check and run Windows Update, schedule runs, read logs and audit drivers.
  • Command-line modes for status, updates, driver audit, log collection and resetting Windows Update.
  • MSI with silent deployment, or a portable EXE.

What carried into WinTool

  • V1 grew into V2, and WinTool carries the V2 engine
  • Scheduled update runs
  • Driver audit and silent deployment
Moving to WinTool?

WinTool finds V1, offers to import its schedule and removes it.
